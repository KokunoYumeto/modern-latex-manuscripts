\section{Створення базових структур даних та матеріалів на базі рушія Bevy мовою Rust}

Для реалізації алгоритму трасування було вибрано ігровий модульний рушій Bevy версії 0.15, написаний мовою програмування Rust для зручного визначення та реалізації графічного пайплайну, і шейдерну мову WGSL для реалізації основних процесів на GPU:
\begin{itemize}[itemsep=0pt, topsep=0pt, label=$\diamond$]
    \item базове трасування кольору орієнтованих воксельних об'єктів на сцені на поверхню обмежувальних коробок (\texttt{VoxelRayTracedMaterial});
    \item відкладене трасування тіней та навколишнього перекриття за допомогою загального воксельного об'єму та G-буферів (\texttt{DeferredRayTraced\-PipelineOptimized}).
\end{itemize}

\subsection{Архітектура системи плагінів матеріалів}

В даній роботи ми визначаємо систему воксельних матеріалів та пайплайнів в межах графу рендерингу рушія Bevy (Bevy Render Graph). Для цього ми створюємо певні плагіни та системи, які відповідають за різні аспекти рендерингу воксельних об'єктів та їх інтеграцію з основним графом рендерингу:
\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item \texttt{VoxelPlugin} --- основний плагін, який включає в себе інші підплагіни, які відповідають за різні аспекти графічного застосунку: 
    \begin{enumerate}
        \item \texttt{Image3dPlugin} --- завантаження двовимірних зрізів 3D моделі у відомих форматах зображення (JPG, PNG тощо) та вивантаження їх у 3D текстури на GPU;
        \item \texttt{WorldVolumePlugin} --- ініціалізація та обробка (заповнення, очищення) загального воксельного об'єму;
        \item \texttt{VoxelRayTracedMaterialPlugin} --- реєстрація та ініціалізація ос\-новного матеріалу для первинного воксельного трасування;
        \item \texttt{RayTracedPostProcessingPlugin} --- плагін пост-процесингу, що\\включає в себе пайплайни відкладеного трасування та очищення\\G-буфера в кінці проходу рендеру \engl{render pass};
        \begin{enumerate}
            \item \texttt{RayTracedAttachmentsPlugin} --- менеджмент компонентів\\G-буфера для відкладеного рендерера.
        \end{enumerate}
    \end{enumerate}
    \item \textit{Додаткові плагіни}: 
    \begin{itemize}[itemsep=0pt, topsep=0pt, label=$\diamond$]
        \item \texttt{MaterialPlugin<DebugVoxelRayTracedMaterial>} --- матеріал для візуального зневадження загального об'єму;
        \item \texttt{ExtractResourcePlugin<DebugOptions>} --- плагін для перетворення ж зневаджувальної конфігурації рендерера для роботи в пайплайні.
    \end{itemize}
\end{enumerate}

\subsection{Організація модульної структури проєкту}

Проєкт організовано за принципом модульної архітектури з чіткою розділеністю відповідальності між компонентами. Кореневі модулі \texttt{lib.rs} та \texttt{main.rs} забезпечують точки входу для бібліотеки та виконавчого файлу відповідно.

Основні модулі проєкту структуровані наступним чином:

\begin{itemize}[itemsep=0pt, topsep=0pt, label=$\diamond$]
    \item \texttt{materials} --- модуль для визначення матеріалів та їх поведінки:
    \begin{itemize}
        \item \texttt{voxel\_ray\_traced.rs} --- імплементація основного матеріалу\\ \texttt{VoxelRayTracedMaterial} для первинного трасування;
        \item \texttt{debug/debug\_voxel\_ray\_traced.rs} --- допоміжний матеріал для візуалізації Voxel World Volume;
    \end{itemize}
    \item \texttt{post\_processing} --- модуль для пост-процесингу та відкладеного рендерингу:
    \begin{itemize}
        \item \texttt{ray\_traced\_attachments.rs} --- управління G-buffer текстурами та їх механіка оновлення;
        \item \texttt{deferred\_ray\_traced.rs} --- реалізація вузла відкладеного рендерингу та світлового проходу;
        \item \texttt{clear\_ray\_traced\_resources.rs} --- системи для очищення ресурсів між кадрами;
    \end{itemize}
    \item \texttt{utils} --- модуль утиліт:
    \begin{itemize}
        \item \texttt{image\_3d.rs} --- завантаження та обробка 3D текстур із 2D зрізів;
        \item \texttt{expand.rs} --- макрос для створення розширень 3D зображень під час компіляції: ``.3d.png'', ``.3d.jpg'' тощо;
        \item \texttt{world\_volume/} --- підмодуль для управління глобальним воксельним простором:
        \begin{itemize}
            \item \texttt{clear.rs} --- compute шейдер для очищення світового об'єму;
            \item \texttt{fill.rs} --- compute шейдер для заповнення світового об'єму воксельними моделями;
            \item \texttt{mip\_gen.rs} --- compute шейдер для генерації MIP-рівнів ієрархічного трасування;
        \end{itemize}
    \end{itemize}
\end{itemize}

Така організація дозволяє легко розширювати функціональність проєкту, тестувати окремі компоненти та підтримувати чистоту кодової бази.

\subsection{Реалізація структури VoxelRayTracedMaterial}

Для забезпечення інтеграції воксельного трасування з графічним пайплайном Bevy було створено спеціалізацію трейту \texttt{Material}. Трейт \texttt{Material} в Bevy визначає інтерфейс для матеріалів, які можуть бути застосовані до 3D об'єктів, та дозволяє налаштовувати їх рендеринг на рівні GPU.

Структура \texttt{VoxelRayTracedMaterial} визначена наступним чином:
\newpage

\begin{rustcode}
#[derive(Asset, TypePath, AsBindGroup, Debug, Clone, Default)]
pub struct VoxelRayTracedMaterial {
    #[texture(0, dimension = "3d", sample_type = "u_int")]
    pub voxels: Handle<Image>,

    #[storage_texture(1, access = ReadWrite, image_format =
R32Float, visibility(fragment))]
    pub depth_texture: Option<Handle<Image>>,

    #[storage_texture(2, access = WriteOnly, image_format =
Rgba32Float, visibility(fragment))]
    pub normal_texture: Option<Handle<Image>>,

    pub alpha_mode: AlphaMode,
}
\end{rustcode}

Дана структура використовує макрос \texttt{AsBindGroup}, який автоматично генерує код для зв'язування ресурсів з GPU. Кожне поле структури анотоване атрибутами, що визначають спосіб його передачі до шейдера:

\begin{itemize}[itemsep=0pt, topsep=0pt, label=$\diamond$]
    \item \texttt{voxels} --- 3D текстура з цілочисельним семплуванням, що містить воксельні дані моделі (binding 0);
    \item \texttt{depth\_texture} --- мапа глибини G-буфера з можливістю читання та запису у фрагментному шейдері (binding 1);
    \item \texttt{normal\_texture} --- мапа нормалей G-буфера з можливістю запису (binding 2);
    \item \texttt{alpha\_mode} --- режим обробки прозорості для інтеграції з існуючим пайплайном рендерингу.
\end{itemize}

Імплементація трейту \texttt{Material} визначає спеціалізовану поведінку рендерингу:

\begin{rustcode}
impl Material for VoxelRayTracedMaterial { ... }
\end{rustcode}

Плагін \texttt{VoxelRayTracedMaterialPlugin} реєструє матеріал в системі Bevy та додає системи для автоматичного управління розмірами воксельних об'ємів.

\subsection{Система компонентів для воксельних об'єктів}

Для коректного відображення воксельних моделей необхідно автоматично адаптувати їх геометричне представлення до фактичних розмірів воксельного об'єму. Для цього введено компонент \texttt{VoxelVolumeSize}, який зберігає тривимірні розміри воксельного простору:

\begin{rustcode}
#[derive(Default, Component, Debug, Clone, ... )]
pub struct VoxelVolumeSize(Extent3d);
\end{rustcode}

Компонент є обгорткою навколо структури \texttt{Extent3d}, яка містить ширину, висоту та глибину текстури у вокселях. Система \texttt{apply\_voxel\_volume\_size} автоматично визначає розміри воксельного об'єму з дескриптора 3D текстури та додає відповідний компонент до сутності ECS \engl{Entity}. А система \texttt{set\_voxel\_volume\_mesh} динамічно оновлює меш-геометрію відповідно до розмірів воксельного об'єму. Вона спрацьовує лише при додаванні компонента \texttt{VoxelVolumeSize} до сутності (перевірка \texttt{size.is\_added()}). Вона виконує наступні операції:

\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item Обчислює фізичні розміри об'єму у світових координатах, множачи\newline кількість вокселів на константу \texttt{VOXEL\_SIZE};
    \item Створює нову кубічну геометрію (\texttt{Cuboid}) з визначеними розмірами;
    \item Налаштовує обмежувальну коробку \texttt{Aabb} \engl{Axis-Aligned Bounding Box} для коректного frustum culling --- відсікання об'єктів поза полем зору камери.
\end{enumerate}

\subsection{Система World Volume}

Системи ініціалізації та обробки світового об'єму визначена в плагіні \texttt{World\-VolumePlugin} і складається з таких компонентів:

\begin{itemize}[itemsep=0pt, topsep=0pt, label=$\diamond$]
    \item \texttt{ExtractResourcePlugin}-и для роботи з ресурсами світового об'єму в пайплайнах;
    \item \texttt{FillWorldVolume} --- вузол і пайплайн для заповнення світового об'єма шляхом інверсивного мапування орієнтованих воксельних об'ємів у нього;
    \item \texttt{ClearWorldVolume} --- вузол і пайплайн для очищення світового об'єму між кадрами;
    \item \texttt{MipGenWorldVolume} --- генерація MIP рівнів для ієрархічного трасування та оптимізації вибору рівня деталізації під час рендерингу;
    \item Функція екстракції даних у \texttt{finish} --- синхронізація колекції воксельних об'ємів між основним та рендер-світом з обчисленням інверсних матриць трансформації для переходу між координатними системами, що використаються пізніше в \texttt{FillWorldVolume}.
\end{itemize}

\subsection{Завантаження воксельних даних з формату 2D\\слайсів}

Завантаження воксельних моделей відбуваються з файлів 2D зображень, експортованих з MagicaVoxel, що містять двовимірні зрізи воксельних об'ємів. Це відбувається асинхронно за допомогою користувацького \texttt{AssetLoader}, що завантажує зображення, ділить його на шари і зберігає у вигляді вбудованого типу \texttt{Image}. Ми обчислюємо кожен наступний піксель, що передається в 1D-масив, за допомогою наступної простої формули:
\begin{equation*}
    P(x,y,c,r) = \begin{pmatrix}
        x + c \times w \\
        y + r \times h
    \end{pmatrix},
\end{equation*}
де $c$ та $r$ --- це поточні стовпець та рядок відповідно, $x$ та $y$ --- поточні координати плитки, а $w$ та $h$ --- ширина та висота однієї плитки.\cite{3dTexture}

\subsection{Теоретичні засади відкладеного рендерингу}

Відкладений рендеринг заснований на тому, що ми переносимо (відкладаємо) обчислення світла, як важке обчислення, на пізніший етап, коли замість вираховування світла (в нашому випадку трасуванням променів) для кожного об'єкту окремо, ми робимо це для всього екрану в цілому. \begin{enumerate}

\subsection{Створення G-buffer attachments}

Для управління текстурами G-буфера та забезпечення їх автоматичного масштабування при зміні розміру вікна було створено компонент \texttt{RayTraced\-Attachments}. Цей компонент прикріплюється до камери та зберігає клю\-чі/ідентифікатори \engl{handle} всіх необхідних текстур для відкладеного рендерингу:

\begin{rustcode}
#[derive(Component, Clone, ExtractComponent)]
pub struct RayTracedAttachments {
    current_size: UVec2,
    pub normals: Handle<Image>,
    pub depth: Handle<Image>,
    pub blue_noise: Handle<Image>,
}
\end{rustcode}

Поля структури мають наступне призначення:

\begin{itemize}[itemsep=0pt, topsep=0pt, label=$\diamond$]
    \item \texttt{current\_size} --- поточний розмір viewport камери у пікселях для відстеження необхідності перестворення текстур;
    \item \texttt{normals} --- ключ мапи нормалей, що заповнюється в проході геометрії;
    \item \texttt{depth} --- ключ мапи глибини;
    \item \texttt{blue\_noise} --- текстура блакитного шуму для покращення якості стохастичних ефектів, таких як ambient occlusion та м'які тіні. Вона завантажується з файлу, \textit{однак не використовується в процесі рендерингу, і \textbf{може} бути використана для візуального покращення в майбутньому}.
\end{itemize}

Система \texttt{add\_attachments} автоматично створює та прикріплює компонент \texttt{RayTracedAttachments} до камер з маркером \texttt{RayTracedPostProcessing}, які ще не мають цього компонента. Вона виконує наступні дії:

\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item Визначає фізичний розмір viewport камери або використовує значення за замовчуванням $1280 \times 720$;
    \item Створює текстури глибини та нормалей з відповідними форматами та прапорцями використання (\texttt{STORAGE\_BINDING} для запису та читання з фрагментних шейдерів);
    \item Прикріплює компонент \texttt{RayTracedAttachments} та \texttt{Jitter} до сутності камери;
    \item Оновлює всі існуючі матеріали \texttt{VoxelRayTracedMaterial}, встановлюючи їм посилання на створені текстури глибини та нормалей.
\end{enumerate}

Система \texttt{resize\_attachments} відстежує зміни розміру вікна та динамічно перестворює текстури G-буфера. При виявленні зміни розміру viewport вона:

\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item Видаляє старі текстури з пам'яті GPU для уникнення витоку ресурсів;
    \item Створює нові текстури з оновленими розмірами;
    \item Оновлює ключі текстур в компоненті \texttt{RayTracedAttachments};
    \item Проходить по всіх матеріалах \texttt{VoxelRayTracedMaterial} та замінює старі хендли текстур на нові.
\end{enumerate}

Система \texttt{update\_jitter} оновлює компонент \texttt{Jitter} для кожної камери, що містить його, генеруючи нові випадкові значення для кожного кадру. Це забезпечує варіативність стохастичних ефектів рей трейсингу і дозволяє використати вбудований метод темпорального згладжування \engl{Temporal anti-aliasing, TAA}.

\section{Написання алгоритму трасування шейдерною мовою WGSL}
\subsection{Шейдер заповнення загального об'єму\\(\texttt{fill\_world\_volume})}

У шейдер ми передаємо 3D текстуру воксельної моделі, що буде мапуватися, на читання, та 3D текстуру загального об'єму на читання та запис, оскільки ми будемо записувати значення вокселів у біти побітовою операцією OR.

Це необхідно для того, щоб не перезаписувати значення бітових \textit{підвокселів}, що вже можуть лежати в даному байтовому вокселі: 1 воксель $\to$ 1 байт $\to$ 8 біт $\to$ 8 підвокселів (0 --- порожній, 1 --- твердий).

Спочатку ми знаходимо центр моделі та загального об'єму, оскільки центр загального об'єму збігається із початком координат, і зсув координат вокселів моделей з урахуванням матриці трансформації відбувається, відповідно, від початку координат. Далі ми знаходимо індекс \textit{підвокселя} в бітовій послідовності Мортона:

\begin{rustcode}
let subvoxel_idx = vec3<f32>(
    f32(w.x * 2u + u32(x)) + 0.5,
    f32(w.y * 2u + u32(y)) + 0.5,
    f32(w.z * 2u + u32(z)) + 0.5
);
\end{rustcode}

Відступ на $0.5$ дозволяє уникнути багу ``стрічок'', які утворюються внаслідок пропуску частин воксельної моделі одиничної товщини. 

А далі використовується проста функція для створення коду Мортона для 1-8 вокселя в сітці $2 \times 2 \times 2$:

\begin{rustcode}
fn morton3(x: u32, y: u32, z: u32) -> u32 {
    return x | (y << 1u) | (z << 2u);
}
\end{rustcode}

\subsection{Шейдер первинного трасування моделей\\(\texttt{voxel\_ray\_traced\_material})}

Цей шейдер виконує первинне трасування променів у воксельних моделях та заповнює G-буфер даними про геометрію сцени. Він складається з вершинного та фрагментного етапів, які працюють разом для визначення видимих воксельних поверхонь.

\textbf{Вершинний шейдер} обчислює початкову точку та напрямок променя для кожної вершини кубічної обмежувальної коробки. Ключовою особливістю є обчислення інверсної матриці трансформації моделі функцією \texttt{get\_local\-from\_world}, яка розкладає інверсію на дві частини: інверсію обертання та інверсію трансляції, що взята з більш нової версії Bevy. Це дозволяє трансформувати світову позицію камери та напрямок променя в локальний простір воксельної моделі:

\begin{rustcode}
out.origin = (local_from_world * 
    vec4<f32>(ray_origin_world, 1.0)).xyz;

out.direction = (local_from_world * 
    vec4<f32>(ray_direction_world, 0.0)).xyz;
\end{rustcode}

\textbf{Фрагментний шейдер} реалізує алгоритм Amanatides \& Woo для швидкого проходження воксельної сітки. Основна функція \texttt{RaymarchVoxels} виконує наступні кроки:

\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item Визначає початкові дані для трасування: 
    \begin{itemize}[itemsep=0pt, topsep=0pt, label=$\diamond$]
        \item точку початку та напрямок променю;
        \item крок \textbf{step} в цілих вокселях;
        \item початковий воксель, звідки починається трасування;
        \item крок \textbf{tDelta} вздовж променя, переміщення $S$ якого дорівнює ширині вокселя;
        \item межу \textbf{tMax}, що описує значення $t$, в якому відбувається перетин межі вокселі для переміщення $S$.
    \end{itemize}
    \item Перевіряє, чи є твердий воксель в обрахованих координатах;
    \item Виконує циклічно класичний алгоритм проходження воксельної сітки, описаний в 2 розділі, але обмежений кількістю кроків \texttt{N = \\volume.w * volume.h * volume.d}.
\end{enumerate}

Алгоритм Amanatides \& Woo забезпечує ефективне трасування, оскільки перевіряє лише вокселі, через які проходить промінь, уникаючи перебору всього об'єму. Обмеження кількості ітерацій сумою розмірів текстури гарантує завершення циклу навіть для найдовших променів.

\subsection{Шейдер відкладеного трасування у воксельному просторі Voxel World Volume\\(\texttt{deferred\_ray\_traced\_effect\_optimized})}

Цей шейдер виконує відкладене трасування променів у загальному воксельному об'ємі для обчислення м'яких тіней та навколишнього перекриття \engl{ambient occlusion, AO}. На відміну від первинного шейдера, який трасує прості модельні об'єми, даний шейдер працює зі складною ієрархічною структурою та використовує побітову оптимізацію вокселів за допомогою коду Мортона.

\subsubsection{Структура ресурсів шейдера:}

\begin{itemize}[itemsep=0pt, topsep=0pt, label=$\diamond$]
    \item \texttt{screen\_texture} --- повноекранна текстура з альбедо/кольором;
    \item \texttt{normals\_texture} та \texttt{depth\_texture} --- мапи G-буфера для реконструкції геометрії;
    \item \texttt{world\_volume} --- 3D текстура MIP-рівнями загального воксельного\\об'єму;
    \item \texttt{jitter} --- uniform буфер з випадковими значеннями для стохастичного семплування;
    \item \texttt{view} --- uniform буфер з матрицями камери та параметрами перегляду;
    \item \texttt{debug\_options} --- push константа для налагодження та налаштування режимів рендерингу.
\end{itemize}

\textbf{Точка входу фрагментного шейдера} \texttt{fragment()} завантажує дані з G-буфера та відображає різні етапи рендерингу згідно з параметром \texttt{debug\-options.mode}. Основний режим (0) відтворює повний пайплайн відкладеного трасування, беручи середнє значення двох повністю відмальованих сцен з різним значенням стохастичної змінної jitter:

\begin{rustcode}
return (
    render(in.uv, color, normal, seed, depth) +
    render(in.uv, color, normal, 
           vec2<f32>(seed.y + 127.1, seed.x + 311.7), depth)
) * 0.5;
\end{rustcode}

\textbf{Функція \texttt{render()}} --- це основна функція рендерингу, що виконує наступні кроки:

\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item Реконструює світову позицію точки за допомогою \texttt{get\_ray\_origin()}, яка використовує inverse projection та inverse view матриці для перетворення UV-координат та глибини в світовий простір;
    \item Обчислює ambient occlusion шляхом виклику \texttt{calculate\_ambient\_occ\-lusion()} з окремим seed для декореляції від тіней;
    \item Генерує стохастичний напрямок променя до площинного джерела світла (тобто такого, що представлене деякою площиною, як ``сонячний диск'', аніж точкою).
    \item Застосовує відступ для уникнення артефактів самоперетину та екстремального тіньового акне: зсув вздовж нормалі та вздовж напрямку променя;
    \item Викликає \texttt{trace\_sparse()} для ієрархічного трасування у world volume з максимальною відстанню \texttt{MAX\_SHADOW\_DISTANCE} та 2 MIP рівнями;
    \item Комбінує результати AO та тіней у фінальне освітлення з врахуванням відстані до перешкоди.
\end{enumerate}

\textbf{Функція \texttt{trace\_sparse()}} реалізує ієрархічне трасування з адаптивним вибором рівня деталізації. Алгоритм працює наступним чином:

\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item Починає з найвищого MIP-рівня (найгрубішої деталізації) для швидкого пропуску порожніх регіонів;
    \item При знаходженні заповненої комірки на високому рівні зменшує MIP-рівень та встановлює прапорець \texttt{rebuild} для перебудови параметрів DDA;
    \item На рівні 0 (найвища деталізація) використовує код Мортона для доступу до підвокселів: розкладає позицію вокселя на біти та обчислює індекс у 8-бітній масці;
\end{enumerate}

\textbf{Функція \texttt{calculate\_ambient\_occlusion()}} обчислює затінення навколиш\-нього перекриття:

\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item Генерує кілька випадкових напрямків у півсфері навколо нормалі за допомогою \texttt{get\_ray\_direction()}, яка використовує семплування в напівсфері;
    \item Для кожного променя застосовує відступ, що вказаний в \texttt{debug\-options};
    \item Трасує промінь на відстань y World Volume;
    \item При знаходженні перешкоди обчислює фактор оклюзії з урахуванням відстані: чим ближче перешкода, тим сильніше затінення;
    \item Усереднює результати.
\end{enumerate}
