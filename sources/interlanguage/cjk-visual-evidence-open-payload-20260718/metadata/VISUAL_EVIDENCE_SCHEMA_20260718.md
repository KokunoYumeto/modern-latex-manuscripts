# CJK visual-evidence schema — version 1.0.0

`VISUAL_EVIDENCE_INDEX.jsonl` is the machine-readable authority; one line represents one preserved image or visual artifact. `VISUAL_EVIDENCE_INDEX.csv` is a lossy inspection projection. Stable `evidence_id` values combine content-hash and lane-relative-path digests, so duplicate bytes in distinct evidentiary locations remain distinct records.

Required fields follow `VISUAL_EVIDENCE_ARCHIVAL_STANDARD_v1_20260718.md`: project/lane/work/language/unit and structural/decision links; evidence role and authority class; exact local and parent asset identity; source/public identifier; parent hash and page/coordinate fields; full-image or crop bounding box; dimensions, DPI, rotation, MIME, bytes, and SHA-256; linked TeX/PDF hashes and page; review, QA, uncertainty, rejected/model-output fields; supersession; rights basis; publication disposition; and continuation cursor.

Null values mean “not proved,” never “not applicable” by silent assumption. Full-page renders receive a full-image pixel bounding box; no semantic sub-page crop is invented. Parent-PDF matching is a deterministic filename/path heuristic and remains reviewable. `open_payload` means project-generated/recovered render evidence with no third-party scan pixels identified. External repository images and scan-page pixels are conservatively `manifest_only_rights_blocked` unless later rights evidence appends a corrected disposition.

Run `python build_validate_package_visual_evidence.py`. The script inventories all supported image extensions under the CJK lane, recalculates dimensions/hashes, validates required fields and dispositions, emits private JSONL/CSV/local manifest/continuity controls, separately emits sanitized public JSONL/CSV and rights-blocked metadata, and creates the exact open-payload ZIP plus checksum list. Absolute workstation paths remain only in private controls and are excluded from the public ZIP. Warnings disclose unresolved parent, DPI, and structural links; integrity errors fail the run.
