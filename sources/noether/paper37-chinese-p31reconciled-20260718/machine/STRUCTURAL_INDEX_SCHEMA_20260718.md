# CJK structural-index schema — version 1.0.0

`CJK_STRUCTURAL_INDEX_20260718.jsonl` is the hierarchy-preserving authority. One JSON object represents one structural unit. `CJK_STRUCTURAL_INDEX_20260718.csv` is a lossy inspection projection generated by the validator/build script.

## Required fields

- `structural_id`: stable deterministic ID (`CJK-STR-<work>-<type>-<ordinal>`); IDs are never recycled.
- `work_id`, `unit_type`, `title`: corpus work and structural classification.
- `parent_id`, `order`: containment parent and source order. Root work records have null parent and order zero.
- `authority`: exact `path`, line/page/span `locator`, SHA-256, and source `language`.
- `targets`: zero or more target records with language, path, locator, SHA-256, match method, confidence, and explicit ambiguity.
- `relations`: typed edges such as `contained_by`; later cross-references and dependencies append here.
- `completion_state`, `review_state`, `publication_state`: separate state axes; none implies another.
- `continuation_cursor`: next work or revisit condition.
- `boundary_confidence`, `ambiguity`: prevents guessed boundaries/correspondences from appearing exact.
- `decision_ids`, `touched_date`: durable provenance.

## Extraction and correspondence rules

TeX section/subsection commands, center apparatus, display delimiters, blank-line prose blocks, and inline footnotes are extracted deterministically. Bibliographic footnotes are classified separately from other notes. Markdown headings and closed blank-line prose/list blocks are extracted. Source-target correspondence uses same-structural-type ordinal matching and is deliberately marked `medium` until human parity confirmation; absent matches remain null/held. File hashes are recalculated on every build. Corrections change the generator and append a difficulty/decision record; stable IDs must not be silently reassigned.

## Validator

Run `python build_and_validate_structural_index.py`. It rebuilds JSONL and CSV, verifies unique IDs, parents, source/target existence and hashes, validates required difficulty-ledger fields and IDs, and writes `VALIDATION_REPORT_20260718.json`. Warnings preserve medium/held correspondence debt; validation fails only on structural, ledger-schema, or integrity errors.
