\chapter{TeX-QA для машинного перекладу прикладної математики}
\label{ch:tex-qa-machine-translation}

\section{Мінімальний контракт для агентів}

Кожен batch-переклад має зберігати таке без зміни:

\begin{enumerate}[label=\arabic*.]
\item математичні формули і порядок множників;
\item команди \verb|\label|, \verb|\ref|, \verb|\eqref|, \verb|\cite|;
\item імена змінних, індекси, транспонування, hats, bars, tildes;
\item структуру theorem/lemma/proof, якщо вона є в джерелі;
\item одиниці вимірювання і розмірності.
\end{enumerate}

Перекладати треба прозу, заголовки, captions, table headings і пояснювальні коментарі. Не треба ``покращувати'' формули, якщо це не окремо позначено як correction patch.

\section{Автоматичні перевірки}

Перший pass після перекладу:
\begin{lstlisting}[language=bash]
# 1. Compile twice.
xelatex -interaction=nonstopmode main.tex
xelatex -interaction=nonstopmode main.tex

# 2. Check for unresolved references.
grep -E "undefined|Undefined|Rerun|multiply defined" main.log

# 3. Check for known bad compute.
grep -R "\\[\\[CHECK\|TODO\|???\|�" -n src/ paper_modules/

# 4. Count labels/refs before and after if source is available.
grep -R "\\label{" source_en/ | wc -l
grep -R "\\label{" source_uk/ | wc -l
\end{lstlisting}

Другий pass - математичний:
\begin{enumerate}[label=\arabic*.]
\item Для матриць перевірити розміри: якщо $H\in\R^{m\times n}$, то $HPH^\T$ має бути $m\times m$.
\item Для кватерніонів перевірити порядок множення: $q\otimes r\ne r\otimes q$.
\item Для груп Лі перевірити, зліва чи справа задається perturbation.
\item Для DSP перевірити $2\pi$, Hz проти rad/s, $f_s/2$ проти $2f_{max}$.
\item Для PDE перевірити знаки Лапласіана, boundary terms і energy identities.
\item Для sensor fusion перевірити напрямок $T_{AB}$ і часові offset.
\end{enumerate}

\section{Глосарний diff}

Кожен новий batch має віддавати список нових термінів у форматі:

\begin{lstlisting}
EN term | UK term | domain | first file | note
\end{lstlisting}

Якщо термін уже є у seed glossary, перекладач не має самовільно вибирати інший варіант. Якщо інший варіант потрібний, він позначається як \texttt{[[CHECK: term-stability]]}.

\section{Форма release card для модуля}

\begin{lstlisting}
MODULE:
SOURCE:
LICENSE / STATUS:
TRANSLATION STATUS:
BUILD COMMAND:
COMPILES: yes/no
KNOWN CHECK FLAGS:
TERMS ADDED:
PUBLIC-SCOPE NOTES:
NEXT ACTION:
\end{lstlisting}

Це виглядає бюрократично, але економить compute: локальний агент не мусить вгадувати, що вже зроблено, що не компілюється, і які рішення словника прийнято.
