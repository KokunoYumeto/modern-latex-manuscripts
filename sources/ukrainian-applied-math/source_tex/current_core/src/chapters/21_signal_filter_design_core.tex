
\chapter{Проєктування цифрових фільтрів: FIR, IIR, вікна, перевірки}

\section{Роль цього розділу}

Попередні розділи дали Fourier/DFT-основу. Тепер потрібна практична TeX-основа для фільтрів: як описати фільтр, як читати амплітудно-частотну характеристику, як пов'язати імпульсну відповідь і згортку, як уникнути помилок на межах дискретизації.

\section{LTI-фільтр}

Для лінійної стаціонарної дискретної системи:
\[
y[n]=\sum_{k=-\infty}^{\infty}h[k]x[n-k].
\]
Це згортка:
\[
y=h*x.
\]
Частотна характеристика:
\[
H(e^{j\omega})=\sum_{n=-\infty}^{\infty}h[n]e^{-j\omega n}.
\]
Якщо $x[n]=e^{j\omega n}$, тоді
\[
y[n]=H(e^{j\omega})e^{j\omega n}.
\]
Тобто комплексна експонента є власною функцією LTI-системи.

\section{FIR-фільтр}

FIR-фільтр має скінченну імпульсну відповідь:
\[
y[n]=\sum_{k=0}^{M} b_k x[n-k].
\]
Його передавальна функція:
\[
H(z)=\sum_{k=0}^{M}b_k z^{-k}.
\]
Переваги: стабільність при скінченних коефіцієнтах, можливість точної лінійної фази, простота перевірки. Недолік: для вузьких переходів може знадобитися великий порядок.

\section{IIR-фільтр}

IIR-фільтр використовує зворотний зв'язок:
\[
y[n]=\sum_{k=0}^{M}b_kx[n-k]-\sum_{k=1}^{N}a_k y[n-k].
\]
Передавальна функція:
\[
H(z)=
\frac{\sum_{k=0}^{M}b_kz^{-k}}
{1+\sum_{k=1}^{N}a_kz^{-k}}.
\]
Стійкість вимагає, щоб полюси були всередині одиничного кола:
\[
|z_i|<1.
\]
IIR часто дає менший порядок, але потребує уважної чисельної реалізації.

\section{Віконний sinc для low-pass FIR}

Ідеальний low-pass у частоті має прямокутну характеристику. Його нескінченна імпульсна відповідь:
\[
h_{\mathrm{ideal}}[n]=
\begin{cases}
\frac{\omega_c}{\pi}, & n=0,\\
\frac{\sin(\omega_c n)}{\pi n}, & n\ne0.
\end{cases}
\]
Щоб отримати FIR, її обрізають і множать на вікно:
\[
h[n]=h_{\mathrm{ideal}}[n-M/2]\,w[n],\qquad n=0,\dots,M.
\]
Вікно зменшує побічні пелюстки, але розширює перехідну смугу. Це типовий компроміс.

\section{Нормована частота}

У DSP дуже часто губляться одиниці. Нехай частота дискретизації $f_s$. Тоді:
\[
\omega = 2\pi \frac{f}{f_s}.
\]
Частота Найквіста:
\[
f_N=\frac{f_s}{2},\qquad \omega_N=\pi.
\]
Якщо фільтр-проєктор очікує нормовану частоту в інтервалі $[0,1]$, треба знати, чи $1$ означає $f_s$ або $f_s/2$. Це не універсально.

\section{Перевірки фільтра}

\begin{enumerate}
\item Побудувати $|H(e^{j\omega})|$ і фазу.
\item Перевірити DC-підсилення:
\[
H(1)=\sum_k h[k].
\]
Для low-pass часто очікується $H(1)\approx1$.
\item Перевірити відповідь на синус відомої частоти.
\item Перевірити імпульсну відповідь і step-response.
\item Для IIR перевірити полюси.
\item Для fixed-point реалізації перевірити переповнення й масштабування.
\end{enumerate}

\section{Різниця між фільтрацією і згладжуванням}

Ковзне середнє:
\[
y[n]=\frac1M\sum_{k=0}^{M-1}x[n-k].
\]
Це фільтр, але з фазовою затримкою. Якщо використовувати симетричне вікно:
\[
y[n]=\sum_{k=-K}^{K}h[k]x[n-k],
\]
то воно некаузальне: потребує майбутніх зразків. Для офлайн обробки це нормально; для реального часу --- ні. У перекладах треба відрізняти \emph{filtering} від \emph{smoothing}, бо в оцінюванні стану ці слова мають ще й окреме байєсівське значення.

\section{Комплексний базовий сигнал}

Для I/Q-сигналу:
\[
x[n]=I[n]+jQ[n].
\]
Зсув частоти на $f_0$:
\[
x_{\mathrm{shift}}[n]=x[n]e^{j2\pi f_0n/f_s}.
\]
Це базова операція цифрової обробки сигналів. У публічному довіднику її треба подавати як загальну математику комплексної огинаючої, а не як інструкцію для конкретного середовища застосування.
