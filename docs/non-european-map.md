# Non-European Mathematics GitHub Coverage Map

Observed 2026-08-06. This page records the exact Chinese, Indian/Sanskrit,
Islamic/Arabic, and historical-reference bytes currently preserved in GitHub.
It is the first page to consult before assigning translation or assembly work.
An unchecked, bilingual, source-facing, partial, or in-progress file is existing
work to inspect; it is not evidence that the language/work is absent.

Claims on this page derive only from the bounded GitHub trees and their exact
custody records. A successful PDF open proves container readability, not
mathematical accuracy, source fidelity, native-language review, or completeness.

  - every direct PDF identity, exact tree digests, repair history, and adverse

Do not use the two-page `00 Project Guide` as the current inventory. It says
62 PDFs / 3,580 pages, describes an older al-Battani surface, and disagrees
with several current names, scopes, and page counts. The exact current surface
is the 72-file shelf bound by the machine manifest.

Many files named “English Translation” are explicitly bilingual or parallel
readers. They are preserved and linked honestly below, but they are not
relabelled as independent English editions. Likewise, an “Original” filename
does not prove that its bytes form a distinct source-language edition.

## Continue Without Duplicating Work

1. Consult this map and the machine manifest before starting any translation.
   In particular, Modern-Chinese Qin fasc.2-4, Arabic *Nine Chapters* vols.1-3,
   Arabic *Sunzi*, English *Fenlei Shishu* vols.1-3, an independent-English Li
   Ye vols.10-12 source, and English Ibn al-Qifti already exist as editable TeX
   even though no matching direct PDF exposes them.
2. Producer-owned successors should assemble/check those existing sources
   before assigning fresh translation. Maintenance must not compile or edit
   them.
3. Produce independent language editions where a current front-facing file is
   only bilingual/parallel; preserve the existing parallel artifact as history.
4. Bind every successor reader to exact source paths, bytes, hashes, scope,
   and supersession. Do not reuse a filename without a new manifest identity.
5. Recover the 59 missing work-level combined-source bundles, 148 source-PDF
   parts, or five historical ZIPs only from exact hash-backed custody; do not
   recreate their bytes from filenames.
6. Replace the stale project guide in a producer-owned successor, while
   preserving the current two-page guide as historical evidence.
7. Treat al-Battani's tables, remaining Arabic descriptions, geography gap,
   and chronology collation as open; inherited “complete” and “critical” names
   are not completion proof.
