# Terminology governance matrix - 2026-06-29

This artifact defines how terminology decisions should move through the Noether multilingual workflow across natural-language lanes, multi-register family lanes, interlanguage/zonal lanes, constructed-language pilots, and computational pivots.

It is not a glossary and not a term-approval ledger. It is a governance model for deciding what a term record means and what authority is required before it can be used in a canonical edition.

Companion machine-readable file: `TERMINOLOGY_GOVERNANCE_MATRIX_20260629.json`

## Term Record Types

| Type | Meaning | Authority level |
| --- | --- | --- |
| `observed_source_anchor` | A term or phrase appears in a source witness. | Evidence only; not approval. |
| `page_inspected_anchor` | A human has checked the source page/context. | Stronger evidence; still not project approval. |
| `project_proposed_term` | The project proposes a term for a draft translation. | Local proposal; requires review. |
| `reviewer_approved_term` | Qualified reviewer accepts the term for a lane/context. | Lane-level authority for the reviewed scope. |
| `accepted_correction_term` | Reviewer correction has been ingested into TeX/glossary/ledger. | Active project term for the specified artifact version. |
| `rejected_term` | Reviewer or evidence rejects the term. | Must not be used without new rationale. |
| `deprecated_term` | Former project term replaced by a better term. | Retained for audit only. |
| `script_sidecar_mapping` | A term is mapped across scripts, such as Latin/Cyrillic or RTL display. | Requires equivalence and render validation. |
| `interlanguage_candidate` | Term proposed or selected for a zonal/interlanguage lane. | Requires language-community/project review. |
| `constructed_pilot_term` | Term designed inside a constructed-language research pilot. | Research-only unless externally adopted/reviewed. |
| `machine_candidate` | AI or script generated a candidate term. | No authority until converted into another type. |

## Decision States

| State | Required evidence | May appear in canonical edition? |
| --- | --- | --- |
| `unreviewed_observed` | Source witness and page reference. | No. |
| `needs_page_inspection` | Automated hit or uncertain OCR/extraction. | No. |
| `page_inspected` | Human page/context check. | Not by itself. |
| `draft_proposed` | Project rationale and source anchors. | Draft only. |
| `review_requested` | Included in reviewer packet. | Draft/review only. |
| `reviewer_approved` | Reviewer decision tied to artifact hash and scope. | Yes, within reviewed scope. |
| `accepted_in_build` | Correction ingested and rebuild validated. | Yes, in that artifact version. |
| `rejected` | Reviewer rejection or source contradiction. | No. |
| `deprecated` | Superseded by accepted term. | No new use. |
| `blocked` | Term lacks authority for intended claim. | No. |

## Lane Rules

### Natural-Language Lanes

- French, Spanish, Simplified Chinese, Japanese, Arabic, Ukrainian, and Russian terms require native-register source evidence and native/technical review.
- Regional variants may be recorded as alternatives, not silently collapsed.
- Machine candidates must become project proposals before review and must never be treated as source evidence.
- Page inspection is required before a term enters a reviewer-facing glossary.

### Multi-Register Family Lanes

- `fa_IR`, `prs_AF`, and `tg_Cyrl_TJ` remain separate unless cross-register authority exists.
- A term approved in one sublane does not automatically transfer to another.
- Shared-term records must list which sublanes approve the term and which remain unresolved.
- Script and directionality evidence is part of the terminology record, not a separate decoration.

### Zonal / Interlanguage Lanes

- Interslavic/Panslavic and any later zonal project must record whether a term is inherited from community resources, selected from cognate families, proposed by this project, or generated by a tool.
- Community/project authority is required before a term can be described as accepted usage.
- Sidecar script mappings need round-trip or equivalence validation.
- A term may be useful for research even when it is not acceptable for learner-facing publication.

### Constructed-Language Pilots

- Constructed-pilot terms must be explicitly marked as designed terms.
- Internal consistency checks can validate morphology, compounding, script, and glossary relations.
- No constructed-pilot term can become a canonical-edition term without external adoption/review and a new lane decision.
- Pilot terms should be versioned so rejected designs remain auditable.

### Computational Pivots

- Alignment or MT pivot terms are tool outputs, not language usage.
- Pivot records must store model/tool version, corpus source, and confidence where available.
- Human language review is required before pivot output becomes reviewer-facing text.

## Governance Invariants

- A source anchor is not a term approval.
- A reviewer decision must identify scope.
- A term approved for one lane is not automatically approved for another.
- Script conversion must preserve mathematical meaning.
- OCR/text extraction uncertainty must remain visible.
- Open-source publication does not make terminology authoritative.
- Constructed-pilot terms are research objects unless adoption/review changes their status.
- Every accepted term should be traceable to source evidence, rationale, reviewer decision, and artifact hash.

## Promotion Path

1. `machine_candidate` or `observed_source_anchor`
2. `page_inspected_anchor`
3. `project_proposed_term`
4. `review_requested`
5. `reviewer_approved_term`
6. `accepted_correction_term`
7. TeX/PDF rebuild and manifest update

Any rejection, OCR uncertainty, lane-transfer question, or script mismatch returns the term to a lower state with a visible rationale.
