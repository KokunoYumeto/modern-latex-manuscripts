## B. Build-type decision rule (F2, made explicit)

1. One dominant written standard already serves the readers → **controlled register** (Arabic, Chinese, Swahili-core, Malay-Indonesian pair).
2. Many standards, high passive recognizability across them → **zonal bridge** (Slavic ✓, Romance ✓, Turkic *if* source floor passes).
3. One register split by writing systems → **script bridge** (Hindustani; Turkic alphabet layer; Persianate Arabic-script/Cyrillic handling).
4. High internal diversity, low mutual recognizability → **no umbrella**: local standards + crosswalks (CJK, Niger-Congo, Indigenous American, creoles as separate registers).
Splitting/combining decisions already taken by the program and confirmed by this rule: no pan-CJK; Malay+Indonesian = one register, two standards; Hindi+Urdu = one register, two scripts; Persianate bridge does NOT inherit into Dari/Tajik (paired review lanes); Dravidian separate from Indic; Berber its own register.

## D. Negative-weight design note (Floris 2026-07-04)
The concept ledger gains a `do_not_use` field per concept per language community: forms with **negative weight**, each with a reason class — `false_friend` (activates wrong concept), `dominance_collapse` (reads as the big language, not the bridge), `loaded` (politically/culturally charged), `register_clash` (colloquial/archaic in target community). Sources: Interslavic false-friend tradition, the Romance warning-comparator statuses, F10-3 rows, and lane rejection matrices (Persianate already builds rejection matrices — same object, per-lane). This makes "avoid X" as first-class and auditable as "prefer Y", which is what selection under the marginal-gain rule needs.
