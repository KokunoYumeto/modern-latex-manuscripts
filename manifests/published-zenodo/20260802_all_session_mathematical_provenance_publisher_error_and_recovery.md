# All-session provenance publisher error and recovery record

Date: 2026-08-02

Release: `all-session-mathematical-provenance-20260802-v3`

Final disposition: all six same-concept successors were published, anonymously
read back, and closed. No target draft remains and no duplicate concept or
parallel draft was created. This file preserves the failed attempts and later
corrections instead of presenting only the successful terminal state.

## Error 1 — invalid generic relation vocabulary

The first explicit publish invocation created the tracked methodology
same-concept draft `21762751`, uploaded its add-only provenance payload, and then
stopped before publication when Zenodo rejected the relation value
`isrelatedto` with HTTP 400. No record had been published.

Correction: the publisher now uses Zenodo's accepted `references` relation for
automatic cross-concept links. A read-only account scan confirmed that draft
`21762751` was the sole methodology draft and was the draft tracked in the
transaction state.

## Error 2 — API display normalization rejected by an over-strict guard

After the relation correction, Zenodo accepted the methodology metadata but the
publisher stopped before publication because the returned metadata was not
byte-for-byte equal to the request. Field-level comparison showed only two
server transformations: removal of an HTML `<hr>` separator and addition of
localized display titles to relation-type IDs.

Correction: the submitted description no longer uses `<hr>`. Exact comparison
still covers relation identifier, scheme, relation ID, order, description, and
every other metadata field, but ignores only Zenodo-added localized relation
display titles.

## Error 3 — overlapping recovery invocation after a local timeout

A local command wrapper reached its time limit while the original publisher
child process continued on Windows. A second recovery invocation briefly
overlapped it and stopped on a transient EGA inherited-file check while the
original process continued serially. The second process did not publish a
record or create a second EGA draft.

Correction: process inspection identified one surviving publisher process. No
further publisher invocation was started. The original process was monitored
through its durable target states until all six were `CLOSED`, then exited
normally. The terminal account-wide scan found no active draft on any target
concept.

## Error 4 — receipt-only absolute paths caught before GitHub publication

The first local readback receipts contained absolute workstation paths in the
`release_spec_path`, upload-manifest path, and summary receipt-path fields. The
Zenodo deposits did not contain those receipt files and were unaffected.

Correction: public receipt fields now use stable repository-relative paths. All
six receipts were regenerated by anonymous readback, then the complete receipt
set passed a JSON parse plus user-home, task-ID, Codex-state, and secret-pattern
scan before Git staging.
